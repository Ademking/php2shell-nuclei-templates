# php2shell test lab

The templates in this repository were tested against a local PHP 8.3.30 lab.
PHP 8.3.30 is inside the affected range (fixed in 8.3.36), and its
`session.upload_progress` handler is the same code path described in the
research.

The research repository ships a Docker lab (`lab/setup.sh`, PHP 8.2.34 FPM +
nginx). Docker was not available in the test environment, so an equivalent
lab was assembled from the PHP 8.3.30 Windows build already installed on the
host plus nginx and php-cgi.

## Components

| Port | Component | Configuration |
| --- | --- | --- |
| 18080 | PHP built-in server | Vulnerable: `upload_progress=On`, `cleanup=Off`, `strict_mode=Off`, `display_errors=On` |
| 18082 | PHP built-in server | `session.upload_progress.enabled=0` (negative control) |
| 18083 | PHP built-in server | `display_errors=0` (negative control) |
| 18085 | PHP built-in server | `session.use_strict_mode=1` (negative control) |
| 18086 | PHP built-in server | `session.upload_progress.cleanup=1` (negative control) |
| 18081 | nginx → php-cgi | `/app` = `php_serialize`, `/api` = `php`, shared save path |
| 18084 | Python HTTP server | Configurable `X-Powered-By` for version-boundary tests |
| 9000 | php-cgi FastCGI | Backend for nginx |

The nginx virtual host is generated by the start script with the current WSL
gateway address, because WSL reaches Windows-hosted php-cgi through that
gateway.

## Start and stop

The PowerShell scripts use the PHP paths from the test environment. Override
the parameters if your installation differs.

```powershell
powershell -ExecutionPolicy Bypass -File .\lab\tools\start_lab.ps1
powershell -ExecutionPolicy Bypass -File .\lab\tools\stop_lab.ps1
```

The start script:

1. Stops previous lab processes.
2. Copies `lab/fixtures` into `C:\Users\ASUS\AppData\Local\Temp\opencode\php2shell-lab`.
3. Writes the lab `php.ini` and nginx configuration.
4. Starts the five PHP built-in servers, php-cgi, nginx, and the version server.
5. Prints the command for the regression suite.

Parameters:

```powershell
.\lab\tools\start_lab.ps1 `
  -PhpExe      'C:\path\to\php.exe' `
  -PhpCgiExe   'C:\path\to\php-cgi.exe' `
  -LabRoot     'C:\path\to\php2shell-lab' `
  -WslDistro   'kali-linux' `
  -WslRepo     '/home/kali/nuclei-template'
```

The generated lab files are outside the repository so that the Windows PHP
processes can serve them without UNC path issues. The version server and
nginx run inside WSL.

## Regression suite

```bash
cd /home/kali/nuclei-template
./lab/tools/test_templates.sh
```

Expected output ends with:

```
RESULT: 29 passed, 0 failed
```

The suite validates every template and covers both positive and negative
cases:

- Active session-fixation check: vulnerable, `upload_progress=Off`,
  `display_errors=Off`, non-PHP.
- Version range: 14 boundaries around 5.4.0, 8.2.35, 8.3.36, 8.4.27, and
  8.5.12.
- LFI chain: vulnerable, `display_errors=Off`, `upload_progress=Off`,
  `use_strict_mode=On`, `cleanup=On`, no LFI.
- Handler mismatch: `php_serialize` → `php`, same `php_serialize`, same
  `php`, non-PHP.

Override the lab addresses through environment variables:

```bash
LAB_HOST=172.28.16.1 LAB_PORT=18080 \
CGI_HOST=127.0.0.1 CGI_PORT=18081 \
SESSION_PATH='C:/Users/ASUS/AppData/Local/Temp/opencode/php2shell-lab/sessions/sess_' \
./lab/tools/test_templates.sh
```

## Helper tools

| File | Purpose |
| --- | --- |
| `lab/tools/upload_probe.py` | Send a single controllable multipart request and print status, headers, and body. |
| `lab/tools/handler_mismatch.py` | Reproduce the Chain C write/read sequence manually. |
| `lab/tools/version_server.py` | HTTP server with a configurable `X-Powered-By` version (`/set?v=8.3.36`). |
| `lab/tools/inspect_sessions.py` | Print the newest injected session file from the Windows lab. |
| `lab/tools/test_versions.sh` | Quick loop over the version boundaries. |
| `lab/tools/test_templates.sh` | Full 29-check regression suite. |

## Important lab notes

- The LFI chain requires `session.upload_progress.cleanup=Off` and
  `session.use_strict_mode=Off`; the default PHP configuration uses
  `cleanup=On` and `strict_mode=Off`. The stock research lab sets cleanup Off.
- The handler-mismatch chain requires `.user.ini` support. The PHP built-in
  server ignores `.user.ini`, which is why the Chain C tests use php-cgi +
  nginx.
- The PHP built-in server is single-threaded. The templates do not need
  concurrency, so this is sufficient for the tests.
- The session files created by the tests are in the `sessions` directory under
  the lab root. They are intentionally left behind for inspection.
- The fixtures only implement the vulnerable surface. They are not a
  production application and do not contain a POP gadget for full Chain C RCE.
